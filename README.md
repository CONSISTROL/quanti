# A股波段交易系统 v4.0

一键运行的A股波段交易系统。`python main.py` 即可完成：数据采集 → 因子打分 → 回测验证 → 生成报告。所有参数通过 `config.json` 配置。

## 快速开始

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 配置（编辑 config.json，填入你的 AI API Key）

# 3. 运行
python main.py
```

输出：
- 终端：回测统计 + 操作记录 + 当前持仓建议
- HTML：`report_YYYYMMDD.html`（收益曲线 + 操作明细 + 选股排名）

> 💡 HTML 报告中的大表格（系统买卖信号记录/选股排名）支持**列筛选 + 分页**：点击表头 ▾ 打开筛选面板——数值列（价格/金额/盈亏等）按范围筛选，枚举列（方向/代码/名称）多选，长文本列（原因）包含搜索；表格上方显示已筛选行数可一键清除。超过 30 行的表格自动**分页**（每页 10/30/50/100 行可切换，‹ › 翻页，页码输入框+跳转按钮直接跳页），筛选后分页自动重算。

**自选池轮动回测（watchlist_backtest）**：

```bash
python run_test.py --module watchlist_backtest
```

- 自选池：`config.json` 的 `watchlist` 字段（股票/ETF/LOF 混合）
- 数据源：按 `data.source`（quantdash 默认，前复权含份额折算）
- 规则：单持仓 100% 满仓轮动，强弱评分卖弱买强（`full_position: true` 时不做强弱分缩放）
- 输出：组合总收益（一次回测两种口径）+ 每只个股独立回测 + ECharts 报告（净值对比/系统买卖信号点K线/用户A操作记录）
- **报告拆分（回测后生成两份独立 HTML，分别对应一个口径）**：
  - `report_signal_<日期>.html`（自选池轮动为 `report_gap_open_signal_<日期>.html` 等）— **信号账户口径**：📋 系统买卖信号记录 + 信号账户统计卡片 + 信号日买卖点曲线
  - `report_exec_<日期>.html`（自选池轮动为 `report_gap_open_exec_<日期>.html` 等）— **用户操作执行口径**：📋 用户A操作记录 + 执行账户统计卡片 + 执行日买卖点曲线
  - 由 `generate_html_report(..., trade_scope='signal'|'exec')` 分别生成；两口径仓位规则不同（信号账户=按信号价满仓、同日多笔等分、不受持仓上限限制；执行账户=按策略仓位规则如 5只×20%），故数字**总是不同**——差异 = 仓位规则 + 成交时点（延迟模式 `exec_next_close`/`buy_next_close` 下再叠加成交价差异）
- **报告分工（一次回测、双账户口径，交易次数天然一致）**：
  - "📋 系统买卖信号记录"（A股多因子量化选股报告 `report_<日期>.html` / 自选池HTML报告）：**信号账户口径**——信号当日按信号价（收盘价）成交的虚拟账户（份额按信号账户自身资金满仓/等分，卖出清仓），记录系统发出信号时点的理论收益（当前配置实测 +968.4%，最大回撤 30.7%）；表内每行含**回撤天数**（持仓期间最高收盘价日 → 卖出信号日的交易日数，卖出日创新高则 0），统计卡片含**最大回撤天数**（信号账户净值从峰值回落的最长持续交易日数，当前实测 406 天）
  - "🔄 用户A操作记录"（自选池轮动分析报告 `report_watchlist_echarts_<日期>.html`）：**执行账户口径**——`exec_next_close` 次日尾盘价成交，记录"信号出来后下一个交易日才操作"的真实收益（当前配置实测 +1759.3%）
  - 两个账户共享**同一批信号/交易流水**（同源于一次回测的 `TradeRecord`），逐笔一一对应、交易次数一致；差异只在成交时点与价格：信号日信号价 vs 执行日执行价，所以总收益率不同（968.4% vs 1759.3%）
- 用户A操作记录：报告底部"🔄 用户A操作记录"表 = 回测交易流水自动生成——假定用户A**忠实执行回测决策、延后1个交易日执行**（信号日 T 收盘收到决策 → 次日 T+1 尾盘/开盘执行），表内每行显示**执行日期（=信号日+1交易日，恒定延迟无需单列信号日）**、方向、价格、数量、盈亏、累计盈亏与信号原因，无需手动填写
- 回测引擎 `TradeRecord` 同时记录信号日口径（`signal_date`/`signal_price`/`pnl_signal`，T 日信号价收益）与执行日口径（`date`/`price`/`pnl_pct`，T+1 执行价收益）；回测结束再重建**信号账户净值**（`signal_equity_curve`/`signal_stats`，信号日按信号价满仓成交、缺失K线前向填充）——"系统买卖信号记录"表取信号日口径 + 信号账户统计（总收益率/回撤等），"用户A操作记录"表取执行日口径 + 执行账户统计

## 策略架构（strategies/ 注册表）

所有策略放在 `strategies/` 文件夹，每个策略一个文件，继承 `BaseStrategy` 接口：

```python
class 策略名(BaseStrategy):
    name = '策略名'           # config.json 中 trading.strategy 配置此值
    label = '显示名称'
    def buy_signal(self, ind, **ctx): ...      # 买入: (is_buy, score, reason)
    def sell_signal(self, ind, entry_price, holding_days, max_profit_seen): ...  # 卖出: (is_sell, reason)
    def rebound_signal(self, ind, prev_close): ...  # 可选: 短线超跌反弹买点
```

**通过 `config.json` 的 `trading.strategy` 选择策略**，新增策略只需在 `strategies/` 加文件并在 `__init__.py` 注册：

| 策略 | 名称 | 特点 |
|------|------|------|
| **reversal**（默认）| 弱转强趋势 | 周线触底四要素+日线右侧确认+超跌反弹，吃完整波段 |
| **momentum** | 动量趋势 | 龙头股 SKDJ 超卖金叉，快进快出 |
| **bollinger** | 布林线均值回归 | 收盘≤下轨买、≥中轨或亏5%卖，适合震荡股 |
| **gap_open** | 跳空高开隔日轮动（涨停收盘复刻版）| 全市场扫描收盘涨幅≥7%的股票（主体为涨停收盘），收盘价买入、次日收盘卖出。2025-2026 牛市区间表现极佳（复刻验证 1905 笔与历史报告一致），弱市慎用 |
| **gap_open_open** | 跳空高开隔日轮动（米筐模板开盘口径）| 全市场扫描**开盘跳空≥3%**+放量的股票（主力净流入代理），**开盘价买入**、次日尾盘卖出。同区间实测 **-80%**，开盘跳空≠收盘强度，高开低走是常态，不建议使用 |

```json
"trading": { "strategy": "reversal" }   // reversal / momentum / bollinger / gap_open / gap_open_open
```

**临时切换策略（不修改 config.json）**：`main.py` / 个股回测支持 `--strategy` 参数，跳空轮动还会自动应用推荐参数（5只等分）：

```bash
python main.py --strategy gap_open              # 全市场跳空高开轮动回测
python main.py --stock 600000 --strategy bollinger  # 单股用其他策略
```

## 交易体系

### 跳空高开隔日轮动（gap_open，涨停收盘复刻版）

**来源**：`report_20260802.html`（+3160.9%/年化+896%/Sharpe 7.63/回撤9.2%/1905笔/胜率56%）逆向工程——该策略代码当时未提交已丢失，从报告交易流水逐笔还原逻辑，并经报告同期数据快照验证复现。

**策略逻辑**（报告实测特征）：
- **买入**：当日**收盘涨幅 >= 7%**（`收盘价/昨收 - 1`，主体为 10% 涨停收盘股；报告买入价=当日收盘价证实为收盘口径，策略名沿袭报告的"跳空高开"叫法），**以收盘价成交**
- **卖出**：持有满 1 个交易日**次日收盘价卖出，无止损**（报告 1905 笔卖出全部为"持有1天到期"）
- **仓位**：5 只等分（每笔=当前现金×20%）

**复刻验证**（`--hist-file hist_batch_20260802.pkl` 报告同期数据快照，2025-01-02 ~ 2026-07-31）：

| 指标 | 复刻 | 报告 |
|---|---|---|
| 交易笔数 | **1905** | 1905 ✓ 完全一致 |
| 胜率 / 盈亏比 | 53% / 1.47 | 56% / 1.51 |
| 最大回撤 | 8.6% | 9.2% |
| 总收益率 | +796.2% | +3160.9% |

首日 5 笔中 4 笔逐笔一致（600186/600191/600255/600272 价格数量全对）。收益差异来源：报告当时的**数据快照不可复得**（前复权基准随除权变化 + 候选扫描顺序差异），导致部分选股不同，无法逐笔复现；策略逻辑本身已完整找回。

> ⚠️ **注意事项**：
> 1. **数据快照敏感**：收盘涨幅信号随前复权基准变化（除权除息后重新抓取，历史涨幅会变），不同日期的数据下回测结果差异巨大（当前 8/3 数据 +111%~+796%，报告当时数据 +3160%）。结论只能代表所用数据快照。
> 2. **区间敏感**：2025-2026 牛市区间大幅盈利；2023-2024 弱势区间（当日 3%+放量变体实测 -25%~-37%）追涨=接盘，**不建议弱市使用**。
> 3. 该策略买入价=收盘价，涨停收盘股实际需排板才能成交，回测为理想化成交。

用法：`python main.py --strategy gap_open` 或 `python tests/backtest_gap_open.py [--days N] [--limit N] [--hist-file 快照] [--next-close] [--max-rise 0.099]`（`--max-rise` 排除收盘涨幅超阈值的股票，模拟涨停买不进）。

**成交时点敏感性实验**（2026-08-04，`--hist-file hist_batch_20260802.pkl` 同区间 2025-01-02 ~ 2026-07-31 对比）：

| 成交模式 | 总收益率 | 年化 | Sharpe | 最大回撤 | 笔数 | 胜率 |
|---|---|---|---|---|---|---|
| 信号当日收盘买入（默认） | +796.5% | +328% | 5.93 | 8.6% | 1882 | 53% |
| 信号次日尾盘买入（`--next-close`） | +19.4% | +12.5% | 0.75 | 20.4% | 939 | 48% |

结论：该策略的收益**几乎全部来自"信号当日以收盘价买入"的成交时点**——次日尾盘入场时涨停溢价已被消化（高开冲高回落），收益从 +796% 骤降至 +19%、Sharpe 5.93→0.75、笔数减半（资金周转率减半）。本质是"打板隔日"博弈，信号当日成交时点不可替代；回测如需模拟真实交易排队，需另设涨停买入限制。

**涨停可成交性实验**（2026-08-04，同区间对比，`--max-rise` 限制收盘涨幅上限模拟"涨停买不进"）：

| 买入范围 | 总收益率 | 年化 | Sharpe | 最大回撤 | 笔数 | 胜率 |
|---|---|---|---|---|---|---|
| 收盘涨幅 >= 7% 不限（默认） | +796.5% | +328% | 5.93 | 8.6% | 1882 | 53% |
| 7% ~ 9.9% 排除涨停收盘（`--max-rise 0.099`） | **-59.2%** | -44.9% | -2.60 | 59.3% | 1801 | 41% |

结论：策略盈利 **100% 来自涨停收盘股**（涨停封板 = 极强次日惯性；涨停股占全部信号约 60%）。只买未涨停的大涨股（7%~9.9%）单独做**直接亏损 -59%**——没能封住涨停本身就说明抛压重，次日大概率回落。因此"涨停买不进"既是该策略的致命弱点也是全部 alpha 来源：真实执行只能靠排板/打板成交率解决，无法通过回测过滤；排除涨停等于消灭策略本身。

每次回测自动生成**两份独立 HTML**：`report_gap_open_signal_<日期>.html`（信号账户口径：同批交易按信号日信号价记账，如延迟模式实测 +752.0%）与 `report_gap_open_exec_<日期>.html`（用户操作执行口径：按实际执行价记账，同批实测 +19.4%）——同一批交易、两种记账，差异即成交时点的影响。

### 跳空高开隔日轮动 — 米筐模板开盘口径复刻版（gap_open_open）

**来源**：米筐（Ricequant）策略模板——`get_iwencai("跳空高开大于3%；主力净流入；低估值；市值小于200亿")` 开盘前选股，09:30 开盘价买入（`handle_bar` 09:30 触发市价单），次日闭市前 3 分钟尾盘卖出（`before_close` 定时器），5 只等分、最多持有 1 个交易日，±90% 止损止盈为无效代码。

**本地实现**（`--strategy gap_open_open`）：全市场扫描，**开盘跳空≥3%**（开盘价/昨收-1，集合竞价 09:25 定盘价）+ **放量确认**（当日量/5日均量≥1.5，代理"主力净流入"，无历史资金流数据）；低估值/市值<200亿跳过（无历史数据，避免前视偏差）。成交价 = **当日开盘价**（`buy_at_open` 模式），次日尾盘收盘价卖出。

**同区间对比**（2026-08-04，8/2 快照，2025-01-02 ~ 2026-07-31）：

| 口径 | 总收益率 | 年化 | Sharpe | 最大回撤 | 笔数 | 胜率 |
|---|---|---|---|---|---|---|
| gap_open（收盘涨幅≥7%，报告复刻）| +796.5% | +328% | 5.93 | 8.6% | 1882 | 53% |
| **gap_open_open（开盘跳空≥3%+放量，模板）** | **-80.3%** | -66.0% | -3.06 | 80.8% | 1799 | 42% |

**结论**：同一批股票池、同一区间，**决策时点从收盘换到开盘，策略从 +796% 变成 -80%**。收盘涨幅（尤其涨停封板）是全天多空博弈的最终裁决，次日惯性极强；开盘跳空只是集合竞价情绪，高开低走是 A 股常态（大部分缺口当日回补），开盘价买入后当日就处于劣势，次日尾盘卖出更是接盘。模板中的"主力净流入/低估值/市值<200亿"条件无法精确复现（无历史数据），但即使加上也难改开盘口径的根本缺陷——**"跳空高开"策略的价值在收盘，不在开盘**。

用法：`python tests/backtest_gap_open.py --strategy gap_open_open [--days N] [--hist-file 快照]`。

### 小市值轮动（EasyQuant 子账户多策略分仓移植）

**来源**：[EasyQuant](https://github.com/HiRenyi/EasyQuant) validated-strategies（聚宽，基准 399101 中小板综指，声称 2022 至今年化 81.8%/回撤 18.3%/Sharpe 2.43）。注：名称"子账户多策略"是噱头，实际为单账户小市值轮动，与"小市值排除3bug版"同源。

**机制**：市值 10~100 亿 + 净利润>0 + 营收>1 亿 + 排除创业板/科创板/北交所/涨停 → 市值从小到大取前 N（N=3~6 由指数 MA10 动态决定，指数强势持仓少）→ 每周二调仓（卖出不在目标列表的，昨日涨停持仓例外不卖）→ 1 月/4 月空仓（持货币 ETF）→ 个股亏损 9% 止损、翻倍止盈。

**本地实现**（`python tests/backtest_smallcap.py [--start 2022-01-01] [--days N] [--hist-file 快照]`）与近似项：
- **市值 = 总股本 × 当日收盘价**，总股本 = 净利润/每股收益（最新财报推导，回测期近似恒定）→ 市值过滤为"回测当日市值"，避免用最新市值回测历史的前视偏差
- 财务过滤（净利>0、营收>1 亿）：最新一期财报（前视偏差，仅影响质量过滤）
- 指数：上证 000001 近似 399101；涨停：收盘涨幅≥9.9% 近似；成交价：当日开盘价近似 10:00 市价

**实测**（8/2 快照）：

| 区间 | 总收益率 | 年化 | 最大回撤 | 胜率 | EasyQuant 声称 |
|---|---|---|---|---|---|
| 380 天（2025-01 ~ 2026-07）| +31.2% | +19.7% | -25.3% | 52% | — |
| 2022 至今（2022-01 ~ 2026-07）| +229.9% | +31.2% | -25.3% | 52% | 年化 81.8% |

**结论**：机制可复现，但收益显著低于原版（年化 31% vs 81.8%）——差异主要来自股票池（399101 成分 vs 全市场主板）与次新股过滤缺失等近似。2026-05/06 小市值杀跌（单月 -11%/-10.7%）为主要拖累，同期 gap_open +796%——2025-2026 是涨停题材行情，小市值因子阶段性失效。另注意：**全区间（2015 起）回测出现 +534 万% 的荒谬数字**——2015 年选股用 2026 年财报/股本过滤=用今天的眼睛挑当年的十倍股，前视幸存者偏差爆炸，长区间结果无参考价值（再次印证本项目的"数据快照敏感"警告，见下节）。

### 成交信息 → 未来上涨概率（三色主力量价代理研究）

`python tests/volume_probability.py` — 全市场 2732 只 × 17 年、741 万日观测的经验条件概率：已知当日量比（VR=当日量/5日均量）与涨跌方向（三色状态）后，未来 1/3/5/10 日上涨概率；含 2022 年前/后两期稳定性检验与"次日开盘买入"可交易口径。

**三色口径**（"短线活跃资金介入"的公开量价代理，与通达信"主力状态三色"同思路，因历史缓存无逐笔/大单数据）：
- **红** = 放量上涨（VR≥1.5，资金介入）｜**绿** = 放量下跌（资金出逃）｜**黄** = 平量/缩量（观望）；涨停/跌停日单独拆出（涨停买不进）

**核心结果**（基准 P(次日涨)=48.8%，P(5日涨)=49.3%，均收益5日 +0.29%）：

| 状态 | 样本量 | P↑1日 | P↑5日 | 均收益5日 | 两期稳定（P↑5） |
|---|---|---|---|---|---|
| 红·放量涨 | 44.5万 | **44.2%** | **45.8%** | +0.05% | ✔ 稳定为负 |
| 红·涨停（买不进） | 5.3万 | 57.5% | 47.7% | +2.15% | ✘ 动量已退化 |
| 绿·放量跌 | 13.1万 | 46.6% | 48.0% | +0.11% | ◐ 仅2022后有效 |
| 绿·跌停 | 0.9万 | 40.7% | 45.2% | -1.00% | ◐ 2022后超跌反弹 |
| 黄·缩量涨 | 31.3万 | 51.0% | **52.3%** | **+0.94%** | ✔ 稳定有效 |
| 黄·缩量跌 | 54.1万 | 50.5% | 49.4% | +0.25% | ◐ |
| 黄·平量 | 592万 | 48.9% | 49.4% | +0.27% | = 基准 |

**结论**：
1. **成交信息能预测，但方向与"量在价先"直觉相反**：放量上涨（"主力介入"信号）次日/5日胜率反而显著低于基准（44.2%/45.8% vs 48.8%/49.3%，前后两期稳定为负）——放量大涨=多空分歧/天量耗竭，追涨负期望；唯一正向强动量是涨停（次日 57.5%），但买不进。
2. **唯一稳定有效的正信号是"缩量上涨"**：P↑5日 52.3%（lift 1.06），均收益 5日 +0.94% vs 基准 +0.29%（3.2 倍），2022 年前后两期均成立，且**次日开盘买入（可交易）口径依然有效**（P↑5=52.1%，均 +0.72%）——缩量上涨=抛压枯竭/浮筹少，延续性好，高开吃掉的部分有限。
3. lift 整体很小（最大 +3pp）：单因子不足以构成高胜率系统；实用方向是**风控**：放量大涨日不追——与 gap_open +796% 收益完全集中在涨停股互相印证（可买入的放量涨普遍负期望，唯有涨停极端日除外）。

#### 多特征概率模型与 Top-N 轮动回测（tests/vol_model_backtest.py）

把单因子升级为 **9 特征 L2 逻辑回归**（vr5/vr20/amt5/chg1~3/up3/pos5/pos20，手写全批梯度下降，无 sklearn 依赖），训练 ≤2018-06、测试 ≥2018-07（454 万日观测）：

| 测试期结果 | 总收益 | 年化 | Sharpe | 最大回撤 |
|---|---|---|---|---|
| 全市场等权基准 | +60.3% | +10.0% | 0.57 | -27.4% |
| 模型每日 Top-5 轮动（无成本） | **-99.97%** | -81.1% | -3.72 | -100% |
| 简单规则：缩量/平量下跌全池等权 | +129.0% | +18.3% | 0.88 | -29.0% |
| 简单规则：剔除当日跌停 | **+215.7%** | **+26.2%** | **1.18** | -25.2% |

**关键发现**：
1. **模型判别力真实但概率≠收益**：测试期按预测概率分十组，P(次日涨) 单调 45.5% → 50.5%（lift +5.3%），但各组平均次日收益不单调——模型能分辨"明天涨不涨"，分不清"涨多少"。
2. **每日 Top-5 巨亏归因**：极端概率尾部的票全是"下跌中的票"（8.6% 买在当日跌停 → 次日平均 -5.0%；17.8% 买在当日跌≥5%）；当日上涨的选股（35.6%）实际是赚的（+0.17%）。**模型把下跌中的票当反弹候选 = 缩量接飞刀**；温和缩量回调次日才均值回归（decile10 深跌组次日 +0.08% vs 非深跌组 +0.01%），跌停/大跌极端票次日继续跌（下跌行情中动量主导）。
3. **零训练简单规则完胜模型**：缩量/平量下跌全池等权（无换手选择），剔除当日跌停后年化 +26.2%、Sharpe 1.18——与三色研究"放量涨负预测"同方向；注意 5 日口径下三色研究的稳定正信号是"缩量上涨"（+0.94%），1 日口径下"温和缩量回调"均值回归成立，两个时点的量能信号方向不同但都真实。
4. **Caveats**：规则为日频全池再平衡、未计交易成本（双边 0.2% 下大部分超额会被侵蚀）、hist 含幸存者偏差、规则方向来自全样本研究（测试期为其子集，轻度样本内选择）。**结论**：日频量价预测的 alpha 只够做风控/择时辅助（如"放量大涨次日别追"），不足以支撑扣除成本后的高胜率日频系统。

### 弱转强趋势策略（当前默认）

**核心逻辑**：周线级别确认底部（低位金叉）后重仓买入，持有到高位转弱卖出。

**买入条件**（需全部满足，评分≥4。周线定趋势定触底、日线定买卖点，右侧交易）：

*周线触底四要素*：
1. **周线SKDJ触底**（必须）：**上一完成周**的周线 K<20 且 0<K-D<5（K 刚上穿 D，股价触底 — 周线金叉/死叉以上周收盘确认，与行情软件一致，避免周内波动误判）
2. **周线超卖**（必须）：价格贴近/低于周线BOLL下轨（价/下轨 < 1.05）— 未跌透的假触底不做
3. **周线MACD止跌**（必须）：周线 DIF-DEA 较前日增长，且非深死叉（DIF-DEA ≥ -0.02）
4. **周线MA5止跌**（加分）：周线 MA5 拐头向上（+1分）

*日线买卖点*：
5. **日线MACD金叉**（必须）：MACD 阴转阳金叉（DIF 上穿 DEA，3 日窗口），或右侧确认（MA5 止跌转涨 且 DIF-DEA 较前一日上涨，金叉趋势已现）
6. **日线SKDJ近3天无死叉**（必须）：SKDJ 死叉时禁止买入
7. **日线SKDJ非高位**（必须）：K>65 不买（不在高位追入）
8. 加分项：日线 SKDJ 低位金叉（K<40）、跌破周线下轨（深度超卖）、**跌破日线BOLL下轨（日线超卖，可做反弹）**、周线MA5拐头、MA5 拐头向上、综合排名 TOP10（+2分）

**短线超跌反弹买点**（独立买点，日线BOLL明显超卖）：
1. 收盘价**明显跌破日线BOLL下轨**（价/下轨 < 0.97，深跌破轨=明显超跌，刚跌破不算）
2. **当日跌幅 ≥ 4%**（急跌超卖，非阴跌 — 区分"超跌反弹"与"下跌中继"）
3. **周线SKDJ K<20**（周线级别超卖确认）
4. 卖出：**反弹到日线BOLL中轨（MA20）** 或 **持有 5 个交易日到期**，止损-5%
5. 示例：000567 2025-04-07 跌停深跌破轨（-10.1%，低于下轨 5.5%）→ 04-14 反弹卖出 +14.4%；而 01-03 仅低于下轨 1.6%（未明显超跌）不触发

**卖出条件**（任一触发）：
1. 日线 SKDJ 高位死叉：K>60 且 K 下穿 D
2. 周线 SKDJ 高位死叉：K>60 且 K 下穿 D（最强信号）
3. 止损：-5%

> 同日规则：卖出当天不买回（避免同日换手白交手续费）

**仓位管理**：最多 4 只；启用凯利公式（`kelly_mode`）时按历史盈亏动态分配，否则每只 25% 资金。设置 `full_position: true` 可强制单笔满仓（跳过按评分缩放，回测示例见下方自选池轮动）

> ⚠️ **关于市场过滤（`market_filter`）的实测结论**：测试了指数 MA20/60/120/250 过滤，虽然能改善 2023 震荡市的磨损（-21.1% → -6.2%），但会成比例砍掉 2024/2026 的独立行情收益（全区间 +713.8% → +89.7%~+248.7%）。自选池（黄金/石油/恒科/半导体）与大盘指数脱钩，大盘过滤砍错对象。**不建议启用** — 2023 年的磨损是趋势策略获取超额收益的固有成本，引擎保留该功能仅供实验。

> ✅ **关于加入纳指ETF（159941）的实测结论**：在自选池加入 159941（纳指ETF广发）后，**全区间 +713.8% → +786.4%，最大回撤 32.7% → 27.4%，2023H2 从 -21.1% 改善到 -1.6%，2024-2026 也从 +310% 增厚到 +321%**。原因：纳指与 A 股自选池行情独立（纳指 2023 独立牛市），隔夜跳空定价型标的提供了真正的分散——2023 震荡期组合自然切换到 159941 避开了 A 股磨损。**这是参数优化做不到的改善，分散化才是解药**。
>
> ✅ **关于自选池优先级（`watchlist_priority`）的实测结论**：159941 设置**优先级+1 是甜点位**（总收益 +786% → **+911%**，2023H2 -1.6% → -0.6%，2024-2026 +321% → +387%，交易仅 245 → 261 笔），代价是最大回撤 27.4% → 33.3%。而**优先级+2 有害**（回撤 → 37.1%，交易翻倍到 474 笔）：159941 振幅小（日均 1.16%）、信号翻转快，+2 的强制度导致频繁换仓，且 2022 纳指熊市死扛深回撤。**建议配置 `"watchlist_priority": {"159941": 1}`，+1 让它在评分接近时优先入选但不过度倾斜**。
>
> ⚠️ **关于日内做T（高抛低吸）的实测结论**：对全部持仓区间模拟三种做T规则——上帝视角（每天捕获30%振幅，+949%）说明理论空间巨大；可执行规则（高开≥1%开盘卖、收盘买回，T+1合规）4只标的3只亏损（-11.6%/-10.2%/-2.9%），因为策略持有的是**趋势延续型强势股**（高开后继续涨概率接近50%、平均还涨0.2%），高抛等于逆势交易；只有"每天抄到日内最低"才赚（+84%），但不可实现。159941（跨境ETF可T+0）虽有日内均值回归特征（高开回落-0.19%、低开反弹+0.24%），但振幅中位数仅0.8%，扣成本后每轮净收益 0.03~0.08%，全期11年累计仅约 +2,200 元（15万本金），无意义。**做T无法在日线数据层面验证为正期望，不建议在系统内实现**。

> ⚠️ **关于成交模式（`exec_next_open` / `exec_next_close` / `buy_next_open`）的实测结论**：真实使用场景是"收盘后看信号、次日操作"，引擎支持三种模拟：`exec_next_open`（买卖都延迟一天开盘成交）、`exec_next_close`（买卖都延迟一天**尾盘收盘价**成交，即 15:57 收盘前手动交易的模拟）、`buy_next_open`（仅买入延迟）。实测（2015-2026全区间）：
> - **买卖延迟的独立分解**（优先级+100）：基准 +1421.7% → 仅买入延迟 +1094.9%（买入追高吃掉327pt，回撤 35.3%→30.9%）→ 买卖都延迟 +113.9%（**卖出延迟单独吃掉约980pt**：高位死叉信号出现后隔夜常低开，晚一天卖=卖在地板价，回撤飙到57.2%）。**卖出延迟才是真实场景的最大成本**。
> - **仅买入延迟**：优先级+1 下 +1156.2%、回撤 29.5%（全部组合里最好：震荡市避开收盘追高，2024-2026 仅少15pt）；优先级+100 下 +1094.9%、回撤 30.9%（比买卖都延迟好一个量级）。
> - **完整真实场景**（买卖都次日，`exec_next_open`）：优先级+1 +1078%、回撤29.8% 远优于优先级+100 +113.9%、回撤57.2%——优先级+100（强制满仓159941）高位死叉后隔夜低开反复回吐，**任何成交模式下都不建议**；优先级+1 是真实可执行的最优配置。
> - **次日尾盘成交（`exec_next_close`，15:57 收盘前手动交易）**：尾盘成交 + 优先级1 = **全组合最优 +1759.3%**、回撤 30.0%、240 笔（胜率49%）——优于收盘即时成交（优先级1 +970.9%）和次日开盘成交（优先级1 +1137.9%）；同样延迟一天，尾盘价优于开盘价（隔夜跳空下开盘价是"恐慌价"，尾盘价更贴近信号价值，且策略信号存在正次日漂移）。**但优先级100 在尾盘成交下仍是最差**（+134.2%/回撤56.9%）：若采用"15:57看信号→次日尾盘手动交易"工作流，应把 `watchlist_priority` 改为 1。

> ⚠️ **关于交易频率的实测结论**：优先100+收盘成交配置下全区间 1021 笔交易（每6个交易日换仓一次），**49% 的持仓只持有 1-2 天、68% 卖出后3日内买回同一代码**——看似信号翻转（whipsaw）过度交易。实测两种降频机制（`min_holding_days` 最短持有期忽略技术性卖出、`death_cross_confirm` 死叉连续N天确认）均有效砍掉交易（1021→529笔，1-2天持仓→2%），**但收益与回撤全面恶化**（+1421.7% → +231.6%~+1025.2%，回撤 35.3% → 38.6%~44.4%）：159941 的 SKDJ 高位死叉/跌破MA20 在纳指慢牛中频繁但有效——1-2 天持仓大部分是**真实回调拐点的逃顶周转**，不是噪声。**保持默认（不降频）是收益最优解**；降频机制作为可选参数保留，需为减少操作频率付出明确收益代价。

> 📌 **次日操作计划（提前一天给手动交易策略）**：`watchlist_backtest` 每次运行末尾自动输出（`daily_plan.py`）——每晚收盘后运行，即可提前一天拿到：
> - **持仓卖出触发价**（明日收盘价达到即卖）：跌破MA20趋势转弱临界、SKDJ高位死叉临界、成本-5%止损线，以及持有的安全区间（收盘在此区间→继续持有）；若今日收盘已触发卖出（如 159941 跌破MA20），直接标记 🚨 明日开盘优先卖出。
> - **切标/买入候选**（卖出后买谁）：按引擎同款打分（含龙头TOP10/优先级加分）排序，并预计算每个候选的**次日买入触发价**——可能在上方（收盘≥P 追涨触发）也可能在下方（收盘≤P 超跌触发），已满足条件的直接标 ✅ 明日开盘即可买。
> - **真实持仓覆盖**：手动交易与模拟有偏差时，在 config `trading.positions` 指定真实持仓（`[{"code": "159941", "entry": 1.574}]`），计划按你的实际持仓给卖出策略，否则用回测最终持仓。

> 🚨 **收盘前检查（15:57 实时价 → 买卖信号 → 飞书推送）**：`python close_check.py --wait` 自动等到交易日 15:57 拉取腾讯实时行情，用最新价≈今日收盘价重算完整技术指标，判定今日买卖信号，**有信号才推送飞书**（`config.json alert.feishu_webhook`）：
> - **卖出信号**：持仓（`trading.positions` 真实持仓）触发止损/跌破MA20/高位死叉 → "⛔ 明日开盘优先卖出"
> - **买入信号**：非持仓候选 buy_signal+引擎加分 ≥ min_buy_score（复刻引擎）→ "✅ 明日开盘可买入"
> - 15:57 最新价≈收盘价但尾盘仍有波动，推送后请人工确认尾盘价格再执行次日操作；`--dry-run` 只打印不推送，无信号不推送（可配合 Windows 任务计划程序每天 15:57 运行）。

## 数据源 (data_sources/)

数据采集独立成 `data_sources/` 文件夹, 通过 `config.json data.source` 选择, 返回格式统一:

| 数据源 | 个股 | ETF | LOF | 说明 |
|--------|------|-----|-----|------|
| **quantdash** (默认) | QuantDash API | QuantDash API | 腾讯 fqkline | 前复权, **正确处理份额折算** |
| **sina** | 新浪 V8 | 新浪基金 | 腾讯 fqkline | 免费无key, 但ETF**不做份额折算复权** |

**为什么推荐 quantdash**: 旧新浪数据源对 ETF 份额折算(如纳指ETF 2022-03-07 1:4折算)不做复权处理, 价格出现假断层, 导致 SKDJ/MACD 等指标失真、回测结果不可信 (159941 数据修正后组合收益 +62.57% → +153.43%)。

**配置**:
- `data.source`: `quantdash` / `sina`, 回测自动读取
- QuantDash API key: 环境变量 `QUANTDASH_API_KEY` 或 `data.quantdash_key` (注册: https://quantdash.net/dashboard)
- 手动刷新缓存:
  - `python -m data_sources.quantdash 601857 159941 160723`
  - `python -m data_sources.sina 601857 159941 160723`
- 缓存: `cache/quantdash_watchlist_YYYYMMDD.pkl` / `cache/sina_watchlist_YYYYMMDD.pkl` (当日有效, 自动增量)

**限制**: QuantDash 免费版**不支持批量接口** (`klines.batch` 需付费升级), 只能单只串行拉取 (单只上限4000根约16年, 支持日/周线)。自选池5只约8秒 + 当日缓存复用, 实际无感; 全市场扫描 (数千只) 仍需 akshare 数据源 (`main.py`)。

**缓存注意**: 修改 `data.hist_days` 后需删除当日缓存 `cache/quantdash_watchlist_YYYYMMDD.pkl`, 否则仍从旧缓存读取。
